Notes from reviewing the PR on DRA's DeviceTaint and ReservedFor.

KEP-5055: DRA: device taints and tolerations
{{< ogp "https://github.com/kubernetes/enhancements/tree/master/keps/sig-scheduling/5055-dra-device-taints-and-tolerations" >}}

When a DeviceTaint is applied, Pods using that device are evicted.
The following code performs the eviction.
{{< github-code "https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/controller/devicetainteviction/device_taint_eviction.go#L1468-L1487" >}}

However, there was a bug where using `return` in the for loop within `handlePods` caused subsequent Pods to not be processed.
{{< github-code "https://github.com/kubernetes/kubernetes/blob/66452049f3d692768c39c797b21b793dce80314e/pkg/controller/devicetainteviction/device_taint_eviction.go#L1447-L1466" >}}

The Pods to be processed are stored in `ReservedFor`, which is exposed via the API as part of ResourceClaim's Status. Since devices can be shared, `ReservedFor` may contain multiple Pods.
{{< github-code "https://github.com/kubernetes/kubernetes/blob/bf0e7b694f3a7355c200241825b6688ad391fae8/pkg/apis/resource/types.go#L1360-L1412" >}}

`handlePod` should probably be executed asynchronously.
